# THE LOST WORLD — Chapter 1 prototype (Unity 6, URP)

Zorvex Entertainment · iOS and Android · third-person jungle adventure

This folder is the Unity project for the first playable prototype (Chapter 1: The Crash).
Everything is generated at runtime from one bootstrap component, so the scene file stays tiny
and free of merge conflicts.

## Status

**Written, not yet run in the Unity Editor.** The C# has been syntax-checked (tree-sitter parse of

## Unity Editor setup (about 5 minutes)

1. **Open the project.** In Unity Hub, *Add project from disk* and pick the `TheLostWorld` folder.
   Install **Unity 6000.0.30f1** with the **Android Build Support** (including OpenJDK and Android SDK/NDK)
   and **iOS Build Support** modules. Another 6000.0.x LTS works too; Unity will offer to upgrade.
2. **Run setup once:** menu **Lost World → Setup Project**. It creates and assigns a mobile URP asset,
   saves the base material into `Resources` (needed so shaders survive device builds), creates
   `Assets/_Game/Scenes/Chapter1.unity` with the `GameBootstrap` object, adds it to Build Settings,
   and applies the player settings (bundle ID, landscape, IL2CPP, ARM64, min OS versions).
   The build commands run this step automatically, so CI needs no manual setup.
3. **Play.** Open `Chapter1.unity` and press Play. The main menu appears. Press **PLAY**.

|---|---|---|

| Run | push the joystick past ~85% | Shift is not bound; run at full stick |

## Building for phones

### From the Editor

| Menu | Output | Use |
|---|---|---|
| **Lost World → Build → Android APK (test install)** | `Builds/Android/TheLostWorld.apk` | Development build, debug-signed. Install with `adb install -r Builds/Android/TheLostWorld.apk` |
| **Lost World → Build → Android AAB (Play Store)** | `Builds/Android/TheLostWorld.aab` | Release bundle for Google Play. Set your upload keystore in *Player → Publishing Settings* first |
| **Lost World → Build → iOS Xcode Project** | `Builds/iOS/` | Open `Unity-iPhone.xcodeproj` on a Mac, set your Team under *Signing & Capabilities*, then Run on a device or *Product → Archive* for TestFlight |

Headless (same code path as CI):

```
Unity -batchmode -quit -projectPath TheLostWorld -buildTarget Android \
  -executeMethod LostWorld.EditorTools.BuildScript.BuildFromCommandLine \
  -customBuildPath Builds/Android/TheLostWorld.apk
```

### From GitHub Actions (no local Unity needed)

`.github/workflows/build-mobile.yml` builds the APK, the AAB and the iOS Xcode project in parallel
on Unity's official CI images (GameCI). Results are attached to the run as downloadable artifacts.

1. Get a Unity license file: follow https://game.ci/docs/github/activation. A free Personal license works.
2. In the GitHub repo, open *Settings → Secrets and variables → Actions* and add `UNITY_LICENSE` (the `.ulf` file contents),
   `UNITY_EMAIL` and `UNITY_PASSWORD`.
3. Optional, for a Play-ready AAB: add `ANDROID_KEYSTORE_BASE64` (`base64 -w0 your.keystore`), `ANDROID_KEYSTORE_PASS`,
   `ANDROID_KEYALIAS_NAME` and `ANDROID_KEYALIAS_PASS`. Without them the AAB is debug-signed and Google Play will reject it.
4. *Actions → Build mobile → Run workflow* (choose all, android or ios), or push a tag such as `v0.1.0`.

The version is `0.1.<run number>`, and the Android version code is the run number, so every upload is unique.

### iOS: what still needs a Mac

The workflow produces an **Xcode project**, not an `.ipa`. Turning it into an installable app needs Xcode on macOS
and an Apple Developer account (signing certificate and provisioning profile). Open the project, select your team,
then build to a connected iPhone or archive and upload to TestFlight.

## Mission flow (Chapter 1)

| # | Mission | Completed by |
|---|---|---|
| 1 | Find Elena | Jason walks to Elena's position (`Trig_FindElena`) |
| 2 | Investigate the crash site | Jason enters the wreck (`Trig_CrashSite`). Logbook and radio are examinable |
| 3 | Follow the ancient trail | Jason walks the stone trail (`Trig_Trail`) |
| 4 | Reach the temple entrance | Jason reaches the plaza (`Trig_Temple`) |
| 5 | Solve the first cooperative puzzle | Jason on the left plate and Elena on the right plate, held 1 s. The temple door opens |

Missions advance strictly in order. `MissionManager.Complete` ignores out-of-order calls.

## Save & checkpoints

- The **SAVE CHECKPOINT** button in the pause menu writes `chapter1_save.json` to `Application.persistentDataPath`.
- It stores: mission index, Jason's position and heading, and whether the puzzle is solved.
- **CONTINUE** on the main menu restores that state. It is greyed out when no save exists.
- **ERASE LOCAL SAVE** in Settings deletes it. All file IO is wrapped in try/catch.

## Monetization (architecture only, no real purchases)

- `IStoreService` is the seam between gameplay and the store. `ProductCatalog` defines the SKUs in the plan:
  Chapter 2, Chapter 3, two cosmetic outfits, and the Complete Adventure bundle. Chapter 1 is free.
- The prototype uses `MockStoreService`. Confirming a purchase in the Store only grants the item locally.
  Nothing is charged, and no store credentials exist in the project.
- **Production:** implement `UnityIapStoreService : IStoreService` on top of Unity IAP (`com.unity.purchasing`),
  with Apple (StoreKit) and Google Play Billing. Put the real SKUs in the App Store Connect and Google Play Console
  and load the Unity Gaming Services project ID from the dashboard. Do **not** commit keys.
  `StoreServiceFactory` is the one place to switch implementations.

## Tuning knobs

Most values are `[SerializeField]` on the components, so you can tune them in the Inspector:
`PlayerController` (speeds, jump), `ThirdPersonCamera` (distance, pitch limits, sensitivity),
`CompanionFollower` (follow and stop distances), `JungleBuilder` (seed, tree/rock/bush counts, terrain size).
